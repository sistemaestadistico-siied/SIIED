SIIED · Oferta de software de código abierto

Documentación del código de toda la plataforma, archivo por archivo, y manuales de operación

El Sistema Integrado de Información Estadística Distrital se construyó íntegramente en la Subdirección de Desarrollo Integral del Departamento Administrativo de Planeación con herramientas libres — Python, Django, PostgreSQL y Three.js. Arquitectura de la plataforma

Una aplicación monolítica modular: un solo despliegue fácil de operar desde una institución pública, con módulos internos desacoplados por carpeta.

Backend · Python + Django

ORM, admin y vistas modulares (views_*.py). Cada módulo de negocio — recolección, validación, editorial, satisfacción, taller — vive en su propio archivo.

Base de datos · PostgreSQL

Esquema versionado con {{ stats_doc.migraciones|default_if_none:"más de 100" }} migraciones Django. Núcleo estadístico, catálogo SDMX, ICED y taller de gestión de datos institucionales conviven con relaciones explícitas.

Frontend · HTML + CSS + JS

Plantillas Django con Tailwind CSS, Font Awesome y Chart.js para los gráficos oficiales. Sin frameworks de cliente: la página funciona sin pasos de compilación.

3D · Three.js

La Maquila de Datos (presentación), la navegación 3D del catálogo y los gráficos interactivos con Don Datico volando entre los datos (modelo GLB animado por rig).

IA · Transformers + embeddings

El asistente Don Datico responde en lenguaje natural sobre indicadores y conjuntos de datos; la ingesta detecta esquemas de archivo automáticamente.

Infraestructura · Whitenoise + WSGI

Estáticos servidos por Whitenoise (en producción vía collectstatic), aplicación desplegable con gunicorn sin configurar un servidor de estáticos aparte.

El código, archivo por archivo

El repositorio en su orden natural: primero el andamiaje del proyecto, luego el modelo de datos, las vistas por módulo, los formularios y asistentes, y las utilidades de soporte.

Núcleo del proyecto

  • manage.py — utilitario de línea de comandos de Django: migraciones, servidor de desarrollo, shell y comandos de administración.
  • myproject/settings.py — configuración: base de datos PostgreSQL, estáticos con Whitenoise, modo DEBUG por entorno, correo y prefijo de despliegue. Las credenciales se leen de .env con python-dotenv.
  • .env.example · .env.production.example — plantillas documentadas de las variables de entorno (desarrollo y producción).
  • myproject/urls.py — enrutador raíz: delega en indicadores/urls.py y en el admin de Django.
  • myproject/wsgi.py · asgi.py — puntos de entrada para gunicorn/uWSGI en producción.
  • requirements-base.txt — dependencias mínimas para operar la plataforma en desarrollo.
  • requirements-production.txt — dependencias del servidor de producción.
  • requirements-ml.txt — dependencias de IA (modelos de lenguaje y embeddings) para el asistente Don Datico.

Modelo de datos (ORM)

  • models.py — el núcleo estadístico: Dominio, Tema, Subtema, Indicador, Gráfico, Dato, Desagregación, Organismo, Menú de dominios, conjuntos de datos, noticias, eventos, productos educativos y académicos, satisfacción y calendario de difusión.
  • models_catalogo.py — metadatos del catálogo de datos: dominios y fuentes de referencia (estándar SDMX).
  • models_iced.py — módulo ICED: operaciones, variables y subíndices del índice de capacidades estadísticas.
  • models_taller.py — taller de gestión de datos institucionales: organismos, asistentes y sesiones del wizard de censo.
  • migrations/ — {{ stats_doc.migraciones|default:"más de 100" }} migraciones que versionan el esquema PostgreSQL: instalar la plataforma es ejecutar migrate.

Manuales de operación

Cómo se instala, opera y mantiene la plataforma — del entorno del desarrollador al servidor de producción.

1 · Instalación para desarrolladores

  1. Clonar el repositorio público: git clone https://github.com/sistemaestadistico-siied/SIIED.
  2. python -m venv .venv, activarlo e instalar requirements-base.txt (y requirements-ml.txt para el asistente de IA).
  3. Copiar .env.example a .env y registrar allí las credenciales: base PostgreSQL, correo, Superset y claves del asistente de IA.
  4. python manage.py migrate → createsuperuser → runserver.

2 · Carga de datos e indicadores

  1. Ingresar al asistente de ingesta con cuenta del equipo estadístico.
  2. Subir el archivo (CSV/Excel): el wizard unificado detecta columnas y propone el esquema.
  3. Mapear dominio → tema → subtema → indicador y completar la ficha técnica.
  4. Publicar: el gráfico aparece en el portal con sus desagregaciones y descargables.

3 · Publicación editorial

  1. Noticias, eventos y productos académicos desde el módulo editorial o el admin.
  2. El calendario de difusión programa su publicación en portada.
  3. Los banners del home toman automáticamente las últimas noticias activas.

4 · Módulos de operación

  • Recolección — operación estadística de campo.
  • Validación — control de calidad de los datos.
  • Delegado — gestión por organismo.
  • Satisfacción — encuestas de experiencia de usuario.
  • Taller de gestión de datos institucionales — censo y prediagnóstico de organismos (DADII).

5 · Asistente Don Datico

  1. Chat en lenguaje natural sobre indicadores y conjuntos de datos.
  2. Motor: views_chat.py + embeddings.py; administración en views_chat_config.py.
  3. Modelos de lenguaje según requirements-ml.txt.

6 · Respaldos y mantenimiento

  1. Respaldo de la base con pg_dump.
  2. Respaldar media/ (archivos cargados) y sentence_models/ (modelos IA).
  3. Al actualizar el código: python manage.py migrate y revisar las migraciones nuevas.

7 · Despliegue a producción

  1. DEBUG=False, ALLOWED_HOSTS y SECRET_KEY en el .env del servidor (nunca en el código).
  2. python manage.py collectstatic: Whitenoise sirve todo desde staticfiles/.
  3. Servir con gunicorn desde myproject.wsgi.
  4. Verificar los estáticos pesados: models/*.glb y audio/ de las páginas 3D.

8 · Páginas de divulgación

  • /presentacion/ — La Maquila de Datos: el show 3D con su línea de tiempo y controles de reproducción.
  • /modelo/ — el diagrama interactivo del modelo de datos.
  • /dominios-3d/ — navegación tridimensional del catálogo.
  • Las páginas 3D de cada subtema incluyen modo de juego con Don Datico.

El modelo de la base de datos

El esquema completo se explora como diagrama interactivo — introspectado en vivo desde el ORM, con búsqueda, filtros por familia y el detalle de cada tabla. Las cuatro familias del modelo:

Núcleo SIIED

Dominios, temas, subtemas, indicadores, gráficos, datos, desagregaciones, organismos y conjuntos de datos.

Catálogo de datos

Metadatos SDMX: fuentes, series y dominios de referencia.

ICED

Operaciones, variables y subíndices del índice de capacidades.

Taller Ecosistema

Censo de organismos, asistentes y sesiones del taller (DADII).
